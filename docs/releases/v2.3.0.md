## ⪩ Retake v2.3.0 ⪨

Long notes stay inside the editor, every review gets a Markdown file with its frame images, and notes that cannot be saved are never lost without asking.

---

### ⤷ Added ˎˊ˗

- **Markdown notes file** — next to `<name>_notes.txt` the notes folder now holds `<name>_notes.md`: the video name, its frame rate, duration, size and note counts, `Reviewer: <name>` from the Author name setting, the general notes, and one heading per frame note with its text and its frame image. It is rewritten after every change and opens in VS Code, Obsidian, Typora or on GitHub. The Done zip carries it as `notes.md`.
- **Retry for notes that are not saved** — when the notes folder cannot be written (a read-only or unplugged drive, a sync program holding the file), the notes stay in the app and a message offers **Retry**. Closing the window, opening another video or restarting for an update first asks **Notes are not saved** with Retry, Discard and Cancel.
- **Read a long note in full** — the selected row of the notes list shows the whole text.

### ⤷ Changed ˎˊ˗

- **Note editor** — the editor keeps its width; a long note wraps, the field grows to six lines and then scrolls. Pasted text with several lines arrives whole, joined into one line.
- **One window per video** — opening a video that another Retake window already has open brings that window to the front instead of opening it twice.
- **Author name** — now written into the Markdown notes file as the reviewer.
- **NTSC frame rates** — 47.952 and 119.88 fps join 23.976, 29.97 and 59.94 at their exact value; other rates such as 99.9 keep the value read from the file.

### ⤷ Fixed ˎˊ˗

- **Long notes ran past the edge of the video** — the end of a long text could not be seen while typing.
- **A failed save lost the typed text** — a note that the app could not take now comes back in the editor with its text.
- **Minimizing during a note** — minimizing the window no longer throws away the note being written.
- **Two windows overwrote each other's settings** — the recent list, frame-rate choices, theme and other settings of one window are no longer erased when another window saves.
- **Frames drifting at 47.952 and 119.88 fps** — notes landed a frame or more off later in long clips.
- **A video whose name starts with a space** could not be opened again after its first note.
- **A settings file that was briefly locked** was set aside and the recent list lost; it is now only set aside when it cannot be read as settings.
- **A damaged path in the recent list** could crash the start screen.
- **Frame images after a failed save** — renamed or deleted images no longer leave notes pointing at missing files.
- **Moving a note and changing its text in one edit** kept the old text when the save failed.
- **Done froze the window** while a large package was written.
- **Long recent lists** — the start screen list and the Recent menu now scroll instead of running off the window.
- **Slow list updates** — thumbnails are no longer decoded again on every change.
- **Long messages and video names** end with an ellipsis instead of running off the window.
- **Typing into the editor from the main window** respects the caret and the selection.
